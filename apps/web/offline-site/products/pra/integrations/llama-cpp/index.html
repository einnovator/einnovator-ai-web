1 · What it is used for

llama.cpp offers broad local and edge reach with a familiar server and CLI boundary.

  • Local agents
  • edge inference
  • desktop applications
  • heterogeneous hardware
2 · Recommended PRA deployment today

Selected Context

Reduce ordinary input context across llama.cpp deployments without changing GGUF model execution.

Compatibility floor: selected ordinary context through the existing engine boundary.

3 · Without engine modification

What works now

  • PRA Gateway targets the OpenAI-compatible server.
  • PRA SDK can assemble selected prompts for CLI or library calls.
  • Normal slot and prompt-state features remain engine-owned.

4 · Native opportunities

What deeper integration could unlock

  • Define an explicit GGUF-compatible non-prefix memory seam.
  • Validate position and model-geometry behavior.
  • Keep semantic-resource identity distinct from slot persistence.

5 · Current evidence

Evidence belongs to a configuration.

Qualification in progress

Selected Context is the recommended compatibility path. Normal slot or prompt-state persistence is not PRA Native Memory; explicit GGUF-native work remains an integration opportunity.

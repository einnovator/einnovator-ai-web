1 · What it is used for

AirLLM exposes the hard case where weight streaming and context-memory movement compete for the same resources.

  • Low-VRAM feasibility
  • consumer GPU experiments
  • large-model research
  • systems prototyping
2 · Recommended PRA deployment today

Selected Context

Reduce selected text without adding another request-path streaming cost to an already bandwidth-constrained workload.

Compatibility floor: selected ordinary context through the existing engine boundary.

3 · Without engine modification

What works now

  • PRA selects ordinary input context before AirLLM generation.
  • The public Transformers-compatible path remains the boundary.
  • Fallback does not require native memory movement.

4 · Native opportunities

What deeper integration could unlock

  • Reduce request-path preparation overhead.
  • Coordinate weight and context transfer schedules.
  • Re-test only when the cost model predicts a credible reuse win.

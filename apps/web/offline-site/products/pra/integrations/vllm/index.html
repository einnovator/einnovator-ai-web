1 · What it is used for

vLLM is a common production choice where compatibility value can be measured before scheduler integration.

  • AI infrastructure
  • cloud inference
  • agent platforms
  • GPU serving fleets
2 · Recommended PRA deployment today

Selected Context

Selected Context can reduce context pressure without changing vLLM; deeper work tests whether reusable non-prefix memory improves matched serving economics.

Compatibility floor: selected ordinary context through the existing engine boundary.

3 · Without engine modification

What works now

  • PRA Gateway sends selected ordinary messages or prompt text.
  • vLLM prefix caching remains independent.
  • Fallback uses the same OpenAI-compatible endpoint.

4 · Native opportunities

What deeper integration could unlock

  • Attach request-local, geometry-matched non-prefix memory.
  • Coordinate immutable reuse with prefix caching.
  • Qualify concurrency, isolation, warm residency, and scheduler ownership.

5 · Current evidence

6 · Known limitations

What is not being claimed

  • Native serving economics are not yet a production claim.
  • Warm-tier transfer and reuse need matched measurements.
  • Tenant and session isolation must remain explicit under concurrency.

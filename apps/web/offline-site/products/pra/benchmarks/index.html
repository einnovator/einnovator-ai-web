PRA/Evidence

PRA evidence and qualification

Compare each optimization against the right baseline.

Selected Context is the compatibility baseline. Native Memory or Native Serving is recommended only when it improves the measured quality-cost frontier.

Context gain

Full Context → Selected Context

Input-token reduction, quality delta, TTFT, throughput, and peak memory where measured.

Native gain

Selected Context → Native Memory

Encoding cost, TTFT, throughput, native K/V bytes, transfer, reuse, and memory.

Serving gain

Native Memory → Native Serving

Prefetch, shared residency, transfer, tail latency, and useful throughput.

Method principle

Freeze selection and quality before comparing infrastructure.

Each row must name the model, engine version, hardware, workload, evidence level, provenance, date, and methodology. Native depth earns promotion only when its incremental contribution survives the matched comparison.

Evidence labels

A status is part of every claim.

Measured

Result exists

The displayed claim has a named source and bounded configuration.

Qualification in progress

Gate remains open

A mechanism or partial result exists, but the recommendation is not complete.

Blocked

Evidence failed a gate

A negative result is retained because it changes the current recommendation.

Not applicable

No claim

The mode or metric does not apply, or the required system is not defined.

PRA is under active systems qualification. Every published metric is tied to a model, engine, hardware environment, workload, and evidence level. Recommendations are updated when new measurements change the frontier.

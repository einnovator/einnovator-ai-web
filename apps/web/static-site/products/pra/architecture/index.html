PRA architecture

Name broadly. Select narrowly. Materialize precisely.

PRA separates semantic resource identity from physical inference memory, so applications can keep a large logical working set without making every token active.

Progressive system

Each layer answers a different question.

01

Typed records

Stable identity, scope, authorization, compact views, and exact backing state.

02

Routing

Semantic, lexical, symbolic, or native addresses score candidate resources.

03

Selection

Policies admit a bounded set of records and chunks under an explicit budget.

04

Materialization

Selected text or qualified native memory enters the current inference operation.

05

Profiles

Model- and engine-specific settings bind quality gates to measured tradeoffs.

Protocol boundary

Agent-facing messages carry logical resources—not raw K/V.

The application and gateway own semantic identity, scope, policy, authorization, and fallback. The engine owns physical native memory. Ordinary text remains the compatibility floor.

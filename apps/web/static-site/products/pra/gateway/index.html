Operating modes

Ordinary engines and PRA-aware endpoints share one boundary.

Fallback is never silent. A request requiring an unsupported capability fails unless text fallback is explicitly allowed.

Ordinary engine

Selected Context

The Gateway renders authorized selected resources as labeled visible context before calling the downstream engine.

pra gateway serve \
  --mode selected-context \
  --backend vllm \
  --backend-url http://127.0.0.1:8000/v1
Capable endpoint

Typed transport

The Gateway preserves typed records, resource inventories or deltas, task/session metadata, and policy for a backend that advertises those capabilities.

pra gateway serve \
  --mode typed-transport \
  --backend sglang \
  --backend-url http://127.0.0.1:30000

Sessions and operations

Logical durability without pretending opaque engine state survived.

Durable snapshots reconstruct logical visibility after a Gateway restart. Engine sessions and cache handles are re-established only when capability and identity checks support reuse.

Security boundary

Logical resources cross the application boundary. Native memory does not.

No raw K/V on the wire

Only an engine adapter creates and consumes model-native memory inside the engine process.

Authorization independent of relevance

A relevant or resident resource is still excluded when the caller cannot materialize it.

Cross-tenant rejection

Resource ownership is checked against the request tenant and remains attached during transport.

Credentials stay out of metadata

Credentials belong in transport headers or provider configuration, not typed PRA records.

Explicit invalidation

Capability loss, stale versions, and incompatible prefix changes force safe resynchronization.

Ordinary-text compatibility floor

Selected Context remains available without an engine patch or model retraining.
